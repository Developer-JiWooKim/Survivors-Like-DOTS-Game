## 1. 컨셉 한 줄

> **불을 지르고, 물을 얼리고, 땅을 부순다.** 무기가 지형을 바꾸고, 바뀐 지형이 다시 무기를 증폭시키는 뱀서라이크.

기존 뱀서라이크와의 차별점은 딱 하나에 건다: **지형이 상태를 가진 시뮬레이션이라는 것**. 기름을 뿌린 곳에 화염구를 쏘면 불이 퍼지고, 물웅덩이에 전격을 쏘면 웅덩이 전체가 감전된다. 이건 "연출"이 아니라 실제 타일 그리드 시뮬레이션이고, DOTS로 하는 이유이기도 하다 (수십만 타일 × 수만 유닛 = Job/Burst가 유일한 답).

## 4. 지형 시스템 ★ 차별화 축

### 4.1 타일 그리드
- 월드는 **1 u = 1 타일**의 고정 그리드. 맵 512×512 타일 (카메라 시야 ~30×17 u).
- 타일 1개 = **4 byte** → 512×512×4 = **1 MB**. 통째로 `NativeArray<TileData>` 싱글턴 보유.

```csharp
struct TileData {          // 4 bytes
    public byte Type;      // 0=흙 1=풀 2=물 3=기름 4=빙판 5=균열 6=바위
    public byte Fuel;      // 연료/잔여량 0~255 (불타면 감소)
    public byte State;     // 비트: 1=연소중 2=감전중 4=오염 8=동결
    public byte Timer;     // 상태 잔여 틱
}
```

### 4.2 타일 종류와 상호작용

| 타일 | 생성 경로 | 플레이어 효과 | 적 효과 | 반응 |
|---|---|---|---|---|
| 흙 | 기본 | - | - | - |
| 풀 | 맵 생성 | - | - | **화염 → 연소, 느리게 확산** |
| 물 | 맵 생성 / 얼음 해동 | - | - | **전격 → 전체 감전** / **냉기 → 빙판** / 화염 저항 |
| 기름 | 기름통 무기 | - | 이동속도 -20% | **화염 → 격렬한 연소, 빠른 확산** |
| 빙판 | 물 + 냉기 | 이동속도 +30% | 미끄러짐(관성) | 15초 후 물로 해동 |
| 균열 | 지진파 | 이동속도 +20% (굴착공) | 이동속도 -40%, 소형 적 낙하사 | - |
| 바위 | 맵 생성 | 통과 불가 | 통과 불가 | 지진파로 파괴 → 흙 |

### 4.3 상태 전파 규칙 (10Hz 틱)
- **연소**: `State |= 1` 인 타일은 주변 4방향 중 `Fuel > 0` 인 풀/기름 타일로 확률 전파. 기름은 전파 확률 3배·피해 2배. 매 틱 `Fuel--`, 0이 되면 소화되고 `Type = 흙`.
- **감전**: 물 타일 하나가 감전되면 **연결된 물 덩어리 전체**가 같은 틱에 감전 (flood fill). 지속 0.5초, 초당 피해.
- **동결**: 물 → 빙판. 15초 후 물로 복귀.
- **오염**: 독이 물에 닿으면 덩어리 전체 오염, 8초 지속.

> 설계 의도: 플레이어가 **준비(기름/물 확보) → 점화**의 2박자 리듬을 학습하게 만든다. 그게 이 게임의 "숙련도"다.

### 4.4 밸런스 안전장치
- **비행 적**은 지형 효과를 전부 무시한다. 지형 콤보 하나로 런 전체를 날로 먹지 못하게 하는 카운터. 10분 이후 비행 비중 20%까지 상승.
- 연소 타일은 **플레이어에게도 피해**를 준다 (방화범 제외). 화면 전체를 불바다로 만들면 자기 무덤.

### 5.1 기본 무기 8종

| # | 무기 | 동작 | 지형 연계 |
|---|---|---|---|
| 1 | 파편탄 | 최근접 적에게 자동 발사 | - (무난한 기본기) |

### 5.2 진화 (무기 Lv.8 + 지정 패시브 Lv.5 → 보급상자)

| 기본 | + 패시브 | = 진화 | 효과 |
|---|---|---|---|
| 파편탄 | 관통 | 궤멸 파편 | 무한 관통 + 벽 반사 |
| 화염구 | 지속시간 | **대화재** | 장판 3배, 연료 무시하고 계속 탐 |
| 서리 파동 | 범위 | 절대영도 | 적 완전 빙결 → 피격 시 파쇄(광역) |
| 전격 사슬 | 연쇄 | 폭풍 | 연쇄 12회, 젖은 적 우선 타겟 |
| 독 안개 | 지속시간 | 역병 | 사망한 적이 새 독 장판 생성 |
| 회전 낫 | 투사체 수 | 파쇄 궤도 | 낫 8개 2중 궤도, 넉백 |
| 지진파 | 범위 | 지각변동 | 균열이 대형 적도 낙하시킴 |
| 기름통 | 투사체 수 | 유전 | 착탄점에서 기름이 스스로 퍼짐 |

### 5.3 패시브 6종
관통 / 범위 / 지속시간 / 연사(쿨감) / 투사체 수 / 유틸(이동속도·자석·재생 택1)

### 5.4 의도된 킬러 콤보 3종
1. **유전 + 대화재** — 맵을 스스로 태우는 영구기관. 가장 강력하지만 자해 위험 최대.
2. **절대영도 + 폭풍** — 빙판 깔고 연쇄 2배. 안정적인 클리어 빌드.
3. **지각변동 + 역병** — 균열로 속도 죽이고 독으로 녹임. 느리지만 가장 안전.

> 3개 다 "무기 2개 + 지형"의 3항 조합이라는 게 포인트. 무기만 모아선 안 나온다.

## 7. 성장

### 7.1 인게임
- XP 젬: 소(1)/중(5)/대(20). **젬도 1만 개가 굴러다닌다** → 젬 전용 풀/자석 Job 필요.
- 레벨업 시 **일시정지 + 3지선다**. (무기/패시브 신규·강화, 이미 6/6이면 강화만 등장)
- 레벨업 필요 XP: `5 + level * 8` (Lv.20 이후 기울기 완만)
- 보물상자: 엘리트 드랍. 진화 조건 충족 시 **진화 무기 확정 획득**.

### 7.2 메타 (골드)
골드 획득: `처치 수 / 10 + 생존 분 × 20 + 보스 처치 500`

| 영구 강화 | 최대 | 단계당 | 누적 비용 |
|---|---|---|---|
| 최대 체력 | 5 | +10 | 100 → 1,600 |
| 공격력 | 5 | +5% | 150 → 2,400 |
| 이동속도 | 3 | +5% | 200 → 1,800 |
| 쿨다운 감소 | 3 | +4% | 250 → 2,250 |
| 픽업 반경 | 3 | +0.5u | 100 → 900 |
| 시작 레벨 | 2 | +1 | 500 → 1,500 |
| 부활 | 1 | 1회 | 3,000 |
| 골드 획득 | 3 | +15% | 300 → 2,700 |

해금: 캐릭터 3종(1,500 / 3,000 / 6,000), 무기 5종(각 800~2,500)

> 영구 강화 총합이 런 난이도를 무력화하지 않도록 상한을 낮게 잡았다 (최대 체력 +50, 공격력 +25%). 실력 대신 시간으로 클리어하는 걸 막기 위함.

### 7.3 저장
`Application.persistentDataPath/save.json` — 골드, 강화 레벨, 해금 목록, 최고 기록. ECS 밖 순수 C# (부트스트랩 MonoBehaviour에서 로드 → Blob/싱글턴으로 주입).

## 8. DOTS 아키텍처

### 8.1 필요 패키지 (현재 미설치 — 첫 작업)
```
com.unity.entities              1.4.x
com.unity.entities.graphics     1.4.x
com.unity.burst                 1.8.x
com.unity.collections           2.5.x
com.unity.mathematics           1.3.x
```
> **Unity Physics는 설치하지 않는다.** 2D 원-원 겹침 판정은 직접 만든 공간 해시가 훨씬 싸다. Unity Physics의 월드 빌드/브로드페이즈 비용은 1만 유닛에서 감당이 안 된다.

### 8.2 시스템 실행 순서 (SimulationSystemGroup)

```

 4. EnemyRecycleSystem         이탈 적 반대편 재배치 (풀보다 우선)
```

### 8.3 핵심 자료구조

**공간 해시 (적)** — 매 프레임 재구축
```csharp
// 셀 크기 1.0 u (적 반경 0.25 u)
NativeParallelMultiHashMap<int, AgentRef> EnemyHash;  // capacity 24,000
struct AgentRef { public Entity E; public float2 Pos; public half Radius; }
```
> 최적화 2단계에서 **카운팅 소트 그리드**(`cellStart: NativeArray<int>` + 정렬된 인덱스 배열)로 교체. 캐시 지역성이 좋아져 이동/충돌 Job이 2~3배 빨라진다. 1차 구현은 MultiHashMap으로 단순하게 간다.

**타일 그리드** — 싱글턴 컴포넌트
```csharp
struct TerrainGrid : IComponentData {
    public NativeArray<TileData> Tiles;   // 512*512
    public int Width, Height;
    public float2 Origin;
}
```
더블 버퍼링(읽기/쓰기 분리)으로 연소 확산을 병렬 Job으로 처리. 쓰기 후 스왑.

**데미지 이벤트**
```csharp
NativeStream DamageStream;               // 병렬 쓰기
struct DamageEvent { public Entity Target; public float Amount; public byte Element; }
```
`ComponentLookup<Health>`에 병렬로 직접 쓰지 않는다 (레이스). 스트림에 모았다가 16번 시스템에서 단일 스레드로 적용 — 1만 이벤트는 단일 스레드로도 0.1ms 수준이다.

**적 스탯** — Blob
```csharp
struct EnemyStatsBlob { public BlobArray<EnemyStats> Stats; }  // TypeId로 인덱싱
// 적 엔티티는 EnemyTypeId(byte)만 보유 → 청크당 엔티티 수 최대화
```

### 8.4 아키타입 설계 원칙
1. **적은 단일 아키타입.** 타입/스탯 분기는 전부 Blob 인덱싱.
2. **구조적 변경 금지.** 생성/파괴 대신 `IEnableableComponent` (`Active`, `Dead`) 토글.
3. **컴포넌트를 작게.** 적 1개당 목표 ≤ 64 byte (`LocalTransform` 32 + `Health` 8 + `EnemyTypeId` 1 + `Velocity` 8 + 머티리얼 프로퍼티). 청크당 256마리 이상 들어가야 한다.
4. `SharedComponent`는 렌더링 배칭 외에 쓰지 않는다.

### 8.5 렌더링
- **Entities Graphics** + 쿼드 메시 1종 + URP Unlit 인스턴싱 머티리얼.
- 스프라이트는 **아틀라스 1장**, 타일 UV 오프셋을 `[MaterialProperty]` 컴포넌트로 전달 → 적 전체가 **드로우콜 1~2개**.
- 애니메이션은 UV 프레임 인덱스 계산으로. `Animator` 미사용.
- 지형은 512×512 `Texture2D`에 타일 상태를 매 틱 기록 → 풀스크린 쿼드 셰이더에서 샘플링. **드로우콜 1개**.
- VFX는 파티클 시스템 대신 **인스턴싱된 쿼드 엔티티**로. `ParticleSystem`은 1만 규모에서 금지.

### 8.6 프레임 예산 (16.6ms 중)

| 항목 | 목표 |
|---|---|
| 공간 해시 재구축 | 1.0 ms |
| 적 이동 + 분리 | 2.5 ms |
| 투사체 이동 + 충돌 | 1.5 ms |
| 지형 틱 (10Hz, 프레임 분산) | 0.5 ms |
| 데미지 적용 + 사망 | 0.8 ms |
| XP 자석 | 0.5 ms |
| 기타 | 1.0 ms |
| **시뮬 합계** | **~7.8 ms** |
| 렌더 (Entities Graphics + URP) | ~5 ms |
| 여유 | ~4 ms |

> 메인 스레드 단독 처리 항목이 0.5ms를 넘으면 설계 오류로 간주하고 Job으로 옮긴다.

## 9. 아트 / 오디오 (프로토타입 단계)

- 전부 **단색 도형**. 플레이어=흰 원, 추격형=빨강 원, 비행=노랑 삼각형, 방패=파랑 사각형, 엘리트=큰 보라 원, 투사체=작은 흰 캡슐.

- 오디오는 M4까지 보류. 단 레벨업/진화/피격 3종은 M3에 임시 SFX라도 넣는다.
- 아트 교체가 **아틀라스 교체 + 머티리얼 프로퍼티 변경**만으로 되도록 처음부터 쿼드+아틀라스 구조 유지.

## 11. 열린 이슈

1. **맵 경계 처리** — 512×512 유한 맵에 벽을 둘 것인가, 무한 스크롤(타일 그리드를 토러스로 래핑)로 갈 것인가. 무한이면 타일 좌표 모듈로 연산이 전면 추가된다. → M3 전에 결정 필요.
2. **연소 확산의 결정성** — 확률 전파에 `Random`을 쓰면 Job 병렬 실행 순서에 따라 결과가 달라진다. 타일 인덱스 기반 해시 난수로 결정적으로 만들 것.
3. **레벨업 일시정지** — DOTS 월드 전체를 멈출지(`World.Time` 스케일 0) 시스템 게이트로 막을지. 후자가 안전.
4. **UI** — UI Toolkit vs uGUI. ECS 밖이라 중요도는 낮지만 레벨업 3지선다 연출 빈도가 높아 초반에 정해두는 게 좋다.
5. **비행 적 비중 20%** 가 지형 빌드를 너무 죽이는지 M4 플레이테스트로 검증.
